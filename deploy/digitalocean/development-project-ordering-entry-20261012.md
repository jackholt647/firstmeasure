# Project ordering and line entry — October 12, 2026

Five development releases after the [resource type work](development-project-categories-20261012.md), each staged, activated and verified on compatibility, web and pool; the last also on the worker.

- `b178dae7` — minimized resource type tabs take their category color. `8869cfae` before it made the minimize animation linear and 0.24s.
- `ebed7483` — Order Materials dialog reduced to one title, the order fields, one tile per material list and the supplier email preview.
- `e4d64cf0` — price book autofill on material names; Enter on a list's last row or in a new list's name starts the next item; the price book opens from a list header and adds to that list; the category header no longer adds items. In the dialog every tile is full height with its dollar total, a delivery date and a free-text time (presets offered); a list without a date can be grouped with one that has one, and only grouped lists share an entry and table in the supplier email. Send Email sends that email through the project's email (`CommsAPI.email.send`) and then records each selected list as ordered, with a calendar entry when it has a date. Nothing is recorded when the send fails. The calendar picker is no longer reachable from the dialog; its code remains. A red Order Materials action opens the dialog with every unordered material list selected.
- `782d5e72` — item entry no longer waits on the server. Adds and edits are applied and focused immediately; `persistVersion` queues each list's saves so every save uses the revision returned by the previous one, and the on-screen items are kept over each server copy while saves remain queued. A failed save reverts only its own item and reports it. Background refresh is held while saves are pending. Tab with a suggestion highlighted takes it and moves to the count; Enter in any cell of a list's last row starts the next row.
- `192109ef` — line item suggestions are data-driven per resource type. `material_resource_types` records gain an optional `line_item_sources` list (`pricebook`, `piece_rate`, `hourly_labor`, `equipment`), defaulting to price book for Materials, piece rate and hourly for Labor, and equipment for Equipment; it is accepted by the existing create and update writers and returned by the catalog. Each column's gear opens Line Item Sources. Suggestions read the price book bridge, the piece rates and hourly rate on the assigned work resource's compensation plan (and its members' plans), and Equipment units with their daily rate. An unassigned labor list has no labor suggestions. The dialog gained an order method selector; only Order by Email is built, and Order with Agent and Log Order Only are labelled placeholders. Order Title was removed; orders are titled from their list.

Not built: suppliers. There is no supplier record or supplier location anywhere in the platform; orders still carry a typed supplier name and email.

Validation: `tests/project-scope-work-browser.test.mjs` (17 passing, covering name commit and Enter, the save queue, delivery grouping and email wording, and source-driven suggestions), `tests/materials-resource-types.test.ts`, `tsc --noEmit`, and the host TypeScript check on every role for `192109ef`. The dialog, autofill and header were rendered in headless Chrome. No order email has been sent and nothing was exercised in a signed-in session.
