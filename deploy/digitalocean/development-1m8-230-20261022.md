# 1M8-230: recent orders missing from the customer portal (2026-10-22)

Linear 1M8-230 (Jacob, urgent): since the 2026-10-20 release, customers' new
reports do not appear under My Projects. A super admin searching the address
makes them appear for the whole account. Reference account: Riedl and Son
Exterior Specialists (`org_cdbda1bcd21d1447`), left unrepaired on purpose.

## Cause

The portal's `list_projects` (`public/portal/scripts/core.js`) lists the
organization's **platform project mirror** whenever it has any rows, and only
imports new FirstMeasure orders into it in the background
(`savePlatformProjectFromFirstMeasure`). Since the 10/20 release the platform
projects API refuses those writes for organizations without
`platform.expanded_access` (no production organization has it), so every
non-expanded account's mirror froze at the release. Their portal kept listing
the frozen mirror.

A super admin has expanded access, so their address search imports the matching
orders into the shared mirror, which is why the workaround fixes them for
everyone.

Read-only production evidence (2026-10-22, compatibility host, read-only
transaction):

- `projects` (FirstMeasure index) for the org has every order through
  2026-10-22 14:11 UTC, with `organization_id` and owner set correctly.
- `platform_documents` collection `projects` for the org was last written
  2026-10-21 05:50 UTC; the org's `app_flags.platform` has no `expanded_access`.
- The issue's screenshot ends at 2537 Sunset Dr (2026-10-20 21:41 UTC), the last
  order before the release.

## Fix

Already on the release candidate: commit `41b65307` (merged via `bad67cf0` into
`codex/release-candidate-20261022`, live on dev as `bc74cedf`). Without expanded
access the portal skips the platform mirror and lists FirstMeasure orders
directly. Production (`8c908166`) does not contain it; `app.1m8.ai` still serves
the ungated `core.js`.

This branch adds a behavioral regression test only (no runtime change):
`tests/portal-regressions-20261021.test.mjs`, "1M8-230: orders placed after the
platform mirror stopped are listed without expanded access". It runs the real
`routeProjectAction('list_projects')` against a stale mirror.

- Fails against production's `core.js` (10d8d525/8c908166): lists only the
  10/20 order.
- Passes on the candidate and against the `core.js` dev serves.
