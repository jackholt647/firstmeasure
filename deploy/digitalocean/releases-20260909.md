## Important unresolved deployment durability risk

The autoscale pool still uses image `244502867`. Its inspected bootstrap downloads the environment overlay and installs historical browser/runtime repairs, but does **not** fetch the current code release. Patching current hosts does not update future replacements: a new node can reintroduce old code and node-local referral writes.

[DigitalOcean documents](https://docs.digitalocean.com/products/droplets/concepts/autoscale-pools/) that changing the droplet template replaces the fleet and temporarily overlaps old and new capacity. Do not make an unreviewed template change while the production database connection budget assumes the current fleet. Prepare a checksum-verified private release bootstrap, assess overlapping-fleet connection demand, coordinate the replacement, and verify a newly provisioned node before declaring this risk resolved. Do not turn the environment-file endpoint into an executable bootstrap or expose private archives publicly.

Tracked as **1M8-173 (High)**. Live read-only checks confirmed eight web processes with pool cap one, worker pool cap four, PostgreSQL maximum 100 connections with three superuser-reserved slots, and 63-67 open connections at sampling time. Twelve overlapping web nodes alone could demand 96 connections before other roles.
