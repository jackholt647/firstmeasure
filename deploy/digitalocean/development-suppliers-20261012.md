# Suppliers, supplier ordering and project projections — October 12, 2026

Four development releases after [project ordering and line entry](development-project-ordering-entry-20261012.md). The first and last changed the API and were staged, activated and verified on worker, compatibility, web and pool; the middle two are frontend-only and went to compatibility, web and pool.

- `bb108b62` — suppliers. A supplier is an external organization connection carrying a supplier role (`SUPPLIER_ROLES` in `materials/suppliers.ts`), not a new kind of object; connection listings hide supplier-only connections unless `relationship_scope` asks for them, so they stay out of Subcontractors. `material_suppliers` holds the catalogue: offerings that point at price book items with an optional supplier SKU and price, order email and a delivery fee (flat amount, optionally free above a threshold). `material_supplier_locations` stores only differences from the supplier (price, carried, SKU, order email, delivery fee) and inherits the rest; `effectiveSupplierOffer`, `effectiveDeliveryFee` and `quoteSupplierDelivery` resolve them. Published as the `suppliers` data provider and four actions; writes need `manage_company_settings`.
- `b1f079ed` — Settings → Price Book → Suppliers. Supplier list and fields, location chips with a count of differences, an items table (carried, SKU, price; inherited values greyed with a reset), and on save an offer to set price book base cost (`internalCost`) to the lowest supplier price. Supplier prices never write the sell price.
- `cfab7338` — ordering from suppliers. In the Order Materials dialog each list picks a supplier or location from a searchable menu that shows only suppliers carrying every item unless the toggle is on, with each total including delivery and the lowest in green. A list defaults to the cheapest supplier that can fill it. Items the supplier does not carry are red with a tooltip and a red flag by the picker; carried items without a price show "unknown" with a yellow flag. Delivery is charged once per delivery and can be switched off; grouped lists share the supplier of the list they are grouped with. One email goes to each supplier. Placing the order writes the supplier's prices and a Delivery line (`metadata.delivery_fee`) into the list, so the order becomes the list's projection; actuals still come only from receipts.
- `eca7774a` — projections. The header shows the projected total of every list on the project, before the tabs. An unordered material list shows a derived Projected delivery row: the fee of the supplier the order would default to, or the lowest fee among suppliers carrying something on the list. It is counted in list, column and project totals, is never stored as a line, is switched off per list with `metadata.projected_delivery_disabled`, and disappears once the list is ordered or has a real Delivery line. `material_resource_types` gains `pricebook_sku_only` (default true for Materials only), set from Line Item Sources as "Only items with a SKU"; when on, price book suggestions leave out items without a code. Order Materials, Work Order and Reserve Equipment appear in the header only while their category has items, sliding in from the right and out again.

Placeholders: Work Order and Reserve Equipment only say they are not built. Order with Agent and Log Order Only remain placeholders. Supplier stock is not modelled.

Known gaps: supplier prices are entered per price book unit, not per supplier order unit. Project lists still project cost from the price book sell price (`unitPrice`), not base cost, until a supplier order replaces it. The calendar picker code in `materials/project.js` is unreachable.

Validation: `tests/materials-suppliers.test.ts`, `tests/materials-resource-types.test.ts`, `tests/project-scope-work-browser.test.mjs` (19 passing, including supplier quotes, default supplier choice, supplier grouping, projected delivery and SKU-only suggestions), `tsc --noEmit`, and the host TypeScript check on every role for the two backend releases. The publication suite had two unrelated failures (custom fields, platform phone) before and after. The dialog, the Suppliers tab and the project header were rendered in headless Chrome with stubbed data. No order email has been sent and nothing was exercised in a signed-in session.
