# SMS registration single submission: development verification

Source commit `7dd83a85fe85c05f13b4870dbaf600772935ebad` removes the prefilled campaign description, tightens field help and validation spacing, clarifies consent copy, hides the screenshot-link character budget, and keeps incomplete-field links at the bottom of each step. Uploaded screenshot evidence links are normalized to the public HTTPS host for existing drafts. New links use `PUBLIC_BASE_URL=https://dev.1m8.ai` on the development HTTP hosts. The number reservation confirmation dialog and the review page's provider/status timeline were removed. Once business verification succeeds, the pending campaign submits from the status refresh without another user action; a failed automatic attempt is recorded and can be retried from the registration screen.

The full messaging suite passed 68 of 69 tests; the existing campaign-replacement refresh test failed only in the full suite and passed alone. The development payload merged concurrent live-host changes before activation.

Public `https://dev.1m8.ai/v1/health/ready` returned the expected release ID and `state=ready`. During post-deployment checks, the public readiness response intermittently included `Legacy state service returned HTTP 503` while the compatibility instance itself reported ready. All three HTTP service processes showed `PUBLIC_BASE_URL=https://dev.1m8.ai`, and the public settings asset contained the updated consent copy. The automatic campaign submission is triggered by registration status refreshes while the settings page is open or when the user returns. It does not run as a background job while nobody opens the registration.
