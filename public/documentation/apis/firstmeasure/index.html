FirstMeasure API Reference

Order FirstMeasure reports, follow their status, and retrieve PDFs, structured measurements, and files. Test mode provides persistent, completed synthetic reports without charging credits or starting production work.

Quickstart

Use the production host for both test and live keys. A test key selects sandbox behavior; a live key commissions billable production work.

Keep API keys on your server. Never embed a live key in browser code, a mobile application, source control, analytics, or logs.

cURL

curl -X POST "https://app.1m8.ai/v1/public/firstmeasure/reports" \
  -H "Authorization: Bearer fmk_test_your_key" \
  -H "Idempotency-Key: 73ff1dfa-698f-4b31-bf0b-4dd445bed43a" \
  -H "Content-Type: application/json" \
  -d '{
    "external_id": "customer-order-1001",
    "address": "1600 Amphitheatre Parkway, Mountain View, CA 94043",
    "project_type": "residential",
    "report_mode": "full",
    "report_expedite_option": "standard_3_6",
    "lat": 37.422,
    "lng": -122.0841,
    "metadata": { "source": "partner-app" }
  }'

Sandbox mode

Test keys begin with fmk_test_.

Safe testing
  • Requests are validated and stored as sandbox report records.
  • New reports return a terminal completed status immediately.
  • Sample PDF, Roofplan XML, parsed JSON measurements, and files are deterministic and retrievable through the normal artifact routes.
  • billing.amount_charged is always 0; billing.quoted_amount shows what the selected configuration would cost.
  • No production queue, FirstMeasure staff work, credit mutation, auto top-up, or live customer delivery is triggered.
Sandbox reports are persistent and can be fetched again with the same test key. The API currently has no outbound completion webhook. Integrations should poll GET /reports/:id; in test mode it normally returns completed on the first check.

Authentication

Send the organization API key in every authenticated request:

Authorization: Bearer fmk_test_your_key

Keys are organization-scoped and mode-scoped. Test keys can access only that organization's test records; live keys can access only its live records. A key may also be restricted by scopes.

ScopeAllows

firstmeasure:files:readList and download files.
firstmeasure:billing:readRead credit and billing state.

Report workflow

1

Create a report with a unique Idempotency-Key, address, project type, and coordinates or structure pins.

2

Store the returned report.id in your own order record.

3

Poll GET /reports/:id with bounded exponential backoff until a terminal status is returned.

4

When completed, download PDFs and read measurements or files through the report-scoped artifact endpoints.

For the initial public integration, send report_mode: "full". If pins are omitted for a live full report, provide lat and lng for the property center; the order can enter needs_structure_pins while FirstMeasure identifies all structures on the parcel.

Billing and pricing

Test-mode responses quote the selected configuration but charge $0. Live report creation charges the organization associated with the key. If configured credits are too low, API auto top-up is attempted; the order is rejected if payment cannot cover it.

ItemCharged priceUnit
Residential full report$7Per report / primary structure
Commercial or multifamily full report$12Per structure
ExpediteDynamicUse GET /pricing for enabled options and current wait-time quote
The charged behavior above is authoritative for order totals. Always use the selected option and quoted totals returned by the API for customer-facing estimates; expedite options and availability can change with queue conditions and organization feature flags.

Expedited service is feature-gated. A request for an option that is not enabled returns feature_not_enabled before the order is created.

Idempotency

Send a stable, unique Idempotency-Key header with every POST /reports. Generate it before the first attempt, store it with your order, and reuse it only when retrying that exact request.

Idempotency-Key: 73ff1dfa-698f-4b31-bf0b-4dd445bed43a

A replay returns HTTP 200 with idempotent_replay: true and the existing report. A new report returns HTTP 201. Never reuse a key for a changed request body or a different customer order.

Statuses and polling

Treat status strings as forward-compatible. The common states below are important, but clients should preserve and display unknown values rather than failing.

StatusMeaningClient action
needs_structure_pinsFirstMeasure still needs structure locations.Continue bounded polling.
queued, pending, processing statesProduction work is not terminal.Poll with backoff; avoid tight loops.
completedReport is terminal and artifacts should be available.Fetch PDF, measurements, or files.
rejected, failed, cancelledTerminal failure.Stop polling and surface rejection/error details.

Recommended development loop: check immediately, then after 1, 2, 4, and 8 seconds, cap the interval, and enforce an overall timeout. Production jobs may take longer; continue later according to your application's job scheduler.

Endpoint reference

GET

/ Metadata

API name, version, and route map. No API key is required.

GET

/pricing?project_type=residential&structure_count=1

Returns test/live mode, standard and enabled expedite options, queue estimate, feature flags, and add-on quote metadata. Requires report-create scope.

GET

/balance

Returns organization credit, ledger, and auto-top-up state. Test mode includes a no-charge explanation.

POST

/reports

Creates a report. Send JSON and an Idempotency-Key. Returns 201 for a new report or 200 for a replay.

GET

/reports?limit=10&external_id=…

Lists mode- and organization-scoped reports. The limit is bounded by the service.

GET

/reports/:id

Returns report summary plus project detail. Test reports return the persistent synthetic project.

GETPOST

/reports/:id/pdf

GET downloads a PDF; optional ?slot=main or ?slot=summary. POST requests generation/refresh and requires PDF-write scope. In test mode POST acknowledges but does not generate production artifacts.

GET

/reports/:id/measurements?format=json|roofplan

Returns parsed JSON or Roofplan XML measurement data.

GET

/reports/:id/files and /reports/:id/files/:name

Lists report artifacts and downloads one by name. Use the returned URL rather than constructing a storage path.

POST

/webhooks/test Request echo diagnostic

This legacy-named route authenticates the caller and echoes its JSON body with receipt metadata. It does not register a webhook, simulate a report event, or send an outbound callback.

Static fixtures

These files are optional client-test inputs for parsers, UI states, and contract tests. They are not simulated API events and are never sent by the service.
